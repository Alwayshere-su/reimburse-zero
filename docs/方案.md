## 1. 项目概述

### 1.1 项目名称

**报销无忧 · 多 Agent 智能稽核与处置闭环**(简称"报销无忧")

### 1.2 一句话定位

以 AgentTeams 为协同设计基点,构建覆盖"单据接收 → 政策稽核 → 风险评级 → 处置执行 → 复盘沉淀"5 个职能 Agent 的费用报销/应付单据端到端处置闭环,让每一笔报销可稽核、可追溯、可审计。

### 1.3 问题与场景

**场景**:企业费用报销与应付单据处理(员工报销、供应商付款申请、差旅/采购/业务招待等费用单据的审核与付款)。

**真实问题**:
- 发票造假、重复报销、拆分报销规避审批、超标费用等资金风险难以全量拦截;
- 人工稽核耗时大(单笔报销平均需数十分钟到数天),标准执行不一致(同一费用不同审核人结论不同);
- 审计追溯难:单据、政策版本、审批记录、付款凭证分散在不同系统,证据链断裂;
- 财务共享中心人员流动大,稽核经验难以沉淀为组织能力。

**目标用户**:企业财务共享中心(审核/出纳/风控岗)、全体员工(报销人)、审计与合规部门。

### 1.4 核心痛点

| 痛点 | 现状 | 期望 |
|---|---|---|
| 稽核效率低 | 人工逐单核对,高峰期积压 | 低风险单据分钟级自动放行 |
| 风险漏检 | 抽检式稽核,重复报销/超标难全量发现 | 全量稽核 + 风险分级 |
| 标准不一致 | 依赖审核人经验 | 政策规则化 + RAG 引用出处 |
| 证据链断裂 | 单据/审批/付款分散 | 全链路 Trace + 审计快照 |
| 经验不沉淀 | 复盘靠文档,无人更新规则 | 复盘 Agent 自动沉淀规则 |

## 2. 场景与价值

### 2.1 场景来源与行业普遍性

费用报销是**每一家企业的刚需业务**,员工规模越大、分支越多,痛点越显著。财政部与审计署对企业费用真实性、发票合规的监管要求持续收紧(如发票电子化、数电票推广),"智能稽核"具备强监管驱动力。场景不依赖特定行业专有数据,可从单企业复制到任意组织(跨行业、跨规模),**行业可复制性极强**。

### 2.2 业务价值

- **效率提升**:低风险单据自动放行,审核人力释放 60% 以上,报销周期从天级压缩到分钟级;
- **风险控制**:全量稽核 + 重复报销检测 + 发票验真,资金风险拦截率显著提升;
- **质量改善**:稽核标准规则化、证据引用化,消除人为差异;
- **体验优化**:报销人实时看到稽核进度与退回原因,不再"石沉大海";
- **知识沉淀**:复盘 Agent 将执行结果回流政策库与规则库,系统越用越准。

### 2.3 输入与输出

- **输入**:报销单/付款申请(含发票影像、费用明细、审批流)、员工与组织信息、财务政策库;
- **输出**:稽核结论(通过/退回/升级)、风险评级、付款指令(须人工确认)、审计报告、规则沉淀。

## 3. 总体架构

### 3.1 架构分层(文字示意)

```
┌─────────────────────────────────────────────────────────┐
│  入口层:报销单 / 付款申请 / 发票影像 / 政策更新           │
├─────────────────────────────────────────────────────────┤
│  协同层:AgentTeams(Manager 编排 + Worker 执行)          │
│     Intake │ 稽核 │ 风险评级 │ 处置 │ 复盘(5 Agent)     │
├─────────────────────────────────────────────────────────┤
│  能力层:Skill(发票验真/政策RAG/重复检测/支付执行/审计)    │
├─────────────────────────────────────────────────────────┤
│  工具层:MCP(税务验真/财务系统/支付系统/消息通知)          │
│  数据层:PolarDB(向量+审计)/ RocketMQ(事件流转)           │
├─────────────────────────────────────────────────────────┤
│  治理层:Higress 网关(鉴权/限流/观测) / Nacos(配置治理)   │
│  可观测:LoongSuite + AgentScope Studio / AgentLoop       │
└─────────────────────────────────────────────────────────┘
```

### 3.2 Agent 分工(5 个职能 Agent,≥3 下限)

| Agent | 职能 | 能力边界(能/不能) | 对应 OpsPilot 骨架 |
|---|---|---|---|
| **Intake 单据接收 Agent** | 接收单据,OCR 结构化、格式校验、查重、分派 | 能:解析/去重/分类;不能:判定费用合规性 | Alert Intake |
| **稽核 Agent** | 政策 RAG 比对、发票真伪核验、超标/违规判定并给引用出处 | 能:按政策条款判定并引用;不能:擅自放宽政策 | RCA |
| **风险评级 Agent** | 综合评级:低风险放行 / 中风险退回补件 / 高风险升级人工审批 | 能:评级与建议;不能:绕过人工审批 | 分类定级 |
| **处置 Agent** | 执行入账/打款(幂等+回滚)/退回补件;打款前强制人工确认 | 能:发起付款/退回;不能:未经审批付款 | Executor |
| **复盘 Agent** | 生成审计报告、统计异常模式、沉淀新规则并建议政策更新 | 能:生成报告/建议规则;不能:直接改政策(需审批) | Postmortem |

### 3.3 AgentTeams 协同设计基点映射(评审重点)

| AgentTeams 能力 | 本方案映射 |
|---|---|
| **角色编排** | Manager 按单据类型/风险域分派:普通报销走 5 Agent 全链;紧急单据走"Intake→稽核→人工"降级链路 |
| **任务拆解** | 一张单据拆为结构化任务 DAG:验真→政策比对→评级→处置→复盘,任务间依赖显式声明 |
| **上下文传递** | 单据对象(结构化数据)+ 会话历史 + 中间结论(如验真结果、引用条款)经共享状态在 Agent 间传递,任一环节失败携带完整上下文回退 |
| **协同执行** | 高风险分支触发人工审批事件(经消息通道通知审批人),审批结果回写驱动流程继续或中止 |
| **状态追踪** | 每笔单据的执行轨迹生成 Span 落库,支持按 TraceId 全链路回放与审计 |

## 4. 多 Agent 闭环设计(赛题 8.3 八步闭环)

1. **任务输入**:员工提交报销单/付款申请,Intake Agent 接收影像与要素,OCR 结构化并做格式校验。
2. **任务拆解**:Intake Agent 将任务拆为"验真、政策比对、风险评级、处置"子任务,经 AgentTeams 分派给对应 Worker。
3. **上下文传递**:单据对象(含发票要素、员工信息、费用明细)与中间结论(验真结果、命中条款)在 Agent 间结构化传递,全程携带 TraceId。
4. **工具调用**:
   - `发票真伪核验 Skill` → 税务验真 MCP(发票全要素核验);
   - `报销政策查询 Skill` → 政策知识库 RAG(向量检索 + 引用出处);
   - `重复报销检测 Skill` → 历史单据向量库(相似度检索);
   - `支付执行 Skill` → 支付系统 MCP(幂等付款,审批前置)。
5. **结果验证**:处置后校验支付回执/入账回执;稽核结论附带证据链(发票验真回执、政策条款引用)供人工复核。
6. **执行证据沉淀**:全链路 Span、结构化 Log(决策依据/失败原因/审批事件)、审计快照落库,关联 TraceId,支持回放。
7. **审批与回滚**:
   - **高风险动作强制人工审批**:打款前必须人工二次确认,超过限额自动升级到更高职级审批;
   - **回滚**:支付失败自动回滚并通知;误放行单据支持发起冲销(红字冲销/撤回入账);
   - **审计**:所有审批、执行动作留痕,满足内部审计与外部监管追溯。
8. **经验沉淀**:复盘 Agent 周期性(或按单据量阈值)分析异常模式(如某部门反复超标、某发票号段集中异常),生成规则建议,经政策管理员审批后回流政策库与规则库,形成"越稽核越聪明"的自进化闭环。

### 异常分支处理

| 异常 | 处理 |
|---|---|
| 税务验真接口超时 | 重试 3 次(指数退避)→ 降级为人工核验任务 |
| 发票 OCR 置信度低 | 标记"需人工复核",跳过自动流程 |
| 政策检索无命中条款 | 标记"无明确条款",升级人工判断 |
| 支付接口失败 | 幂等重试 + 自动回滚,回执与失败原因入库 |
| 审批人超时未处理 | 超时提醒 → 升级到上一级审批人 |

## 5. Skill 工程化设计(本赛题必选项,25% 权重核心)

### 5.1 Skill 总览

| Skill 名称 | 类型 | 复用场景 |
|---|---|---|
| `发票真伪核验` | 外部数据校验 | 报销稽核、供应商付款、发票台账管理 |
| `报销政策查询` | 知识库 RAG | 稽核判定、员工自助咨询、审计比对 |
| `重复报销检测` | 相似度检索 | 费用稽核、供应商重复付款防重 |
| `支付执行` | 资金操作 | 应付付款、差旅结算、退款 |
| `审计报告生成` | 文档生成 | 月度审计、监管报送、风控复盘 |

### 5.2 核心 Skill 九项说明(赛题 9.1 要求)

#### 5.2.1 `发票真伪核验` Skill

| 项目 | 说明 |
|---|---|
| **名称** | 发票真伪核验 |
| **用途** | 核验发票真伪、票面要素一致性(发票号/金额/税号/开票日期),拦截假票与变造票 |
| **输入** | 发票代码、发票号码、开票日期、不含税金额、销方税号(必要时附发票影像) |
| **输出** | 核验结果(真/伪/无法判定)、税局返回明细、核验时间与 TraceId |
| **调用条件** | Intake 完成结构化后、稽核 Agent 判定合规性之前;同一发票 24h 内不重复调用(缓存) |
| **依赖工具** | 税务发票验真 MCP(连接税局接口或合规第三方服务) |
| **失败处理** | 接口超时指数退避重试 3 次;连续失败降级为"待人工核验"任务并通知稽核 Agent;不阻塞整单流程 |
| **安全边界** | 仅稽核 Agent 可调用;调用留痕;发票要素脱敏后缓存;验真结果不可被 Agent 篡改(只读回执) |
| **复用价值** | 任意含发票的业务(报销/应付/台账)均可复用;可作为独立工具开放 |
| **与协同流程关系** | 稽核 Agent 依赖其输出作为合规判定的核心证据之一 |

#### 5.2.2 `报销政策查询` Skill

| 项目 | 说明 |
|---|---|
| **名称** | 报销政策查询(知识库 RAG) |
| **用途** | 按员工职级/费用类型/地区检索报销政策条款,返回带出处的判定依据 |
| **输入** | 员工职级、费用类型、金额、地区、日期 |
| **输出** | 命中条款列表(条款原文 + 政策版本 + 相似度)、适用范围、有无明确限制 |
| **调用条件** | 稽核 Agent 对每笔费用做合规判定时;员工自助咨询时 |
| **依赖工具** | 政策知识库(向量库 + 文档解析),MCP 接入数据源 |
| **失败处理** | 无命中条款 → 返回"无明确条款"并升级人工判断,不臆造政策;向量库故障 → 降级关键词精确检索 |
| **安全边界** | 政策按版本管理,未发布版本不可检索;检索记录留痕;跨部门政策权限隔离 |
| **复用价值** | 政策库模板化,任意企业替换政策文档即可复用;适用于差旅/采购/招待等多费用类型 |
| **与协同流程关系** | 稽核 Agent 的核心判定依据;结果同时沉淀为执行证据供审计引用 |

#### 5.2.3 `重复报销检测` Skill

| 项目 | 说明 |
|---|---|
| **名称** | 重复报销检测 |
| **用途** | 检测同一发票/费用要素在历史单据中的重复提交(重复报销、一票多报、拆分报销) |
| **输入** | 发票号码、销方、金额、费用日期、报销人 |
| **输出** | 相似单据列表(相似度评分 + 命中单据号)、判定建议(疑似重复/正常) |
| **调用条件** | Intake 查重 + 稽核 Agent 二次校验 |
| **依赖工具** | 历史单据向量库(向量化存储) |
| **失败处理** | 向量库故障 → 降级精确匹配(发票号/金额相等);检索超时 → 标记"未完成查重"并人工复核 |
| **安全边界** | 历史数据脱敏后入库;仅稽核链路可查;命中结果不做最终结论,需稽核 Agent 复核 |
| **复用价值** | 供应商重复付款防重、差旅一票多报检测等均可复用 |
| **与协同流程关系** | 稽核 Agent 依赖其输出判定风险等级;结果进入执行证据链 |

#### 5.2.4 `支付执行` Skill

| 项目 | 说明 |
|---|---|
| **名称** | 支付执行(资金操作) |
| **用途** | 对通过审批的单据发起付款/入账,保证幂等与可回滚 |
| **输入** | 付款指令(单据号、收款方、金额、付款账户、审批回执) |
| **输出** | 支付回执(成功/失败、流水号、失败原因) |
| **调用条件** | **必须携带人工审批回执**;审批回执缺失或过期一律拒绝执行 |
| **依赖工具** | 支付系统 MCP(连接资金/银行接口) |
| **失败处理** | 幂等控制(同一单据不可重复付款);失败自动回滚并入库;重试需重新走审批 |
| **安全边界** | 付款金额限额分权(超限自动升级审批);仅处置 Agent 可调;双人复核(审批人 + 出纳角色) |
| **复用价值** | 应付付款、退款、差旅结算等一切资金动作可复用 |
| **与协同流程关系** | 处置 Agent 唯一资金出口;审批与回滚机制即赛题"高风险动作审批/回滚/审计"的直接体现 |

#### 5.2.5 `审计报告生成` Skill

| 项目 | 说明 |
|---|---|
| **名称** | 审计报告生成 |
| **用途** | 按单据/时间/部门维度汇总证据链,生成结构化审计报告 |
| **输入** | 审计范围(时间区间、部门、单据状态)、证据链查询条件 |
| **输出** | 结构化审计报告(单据清单、稽核结论、异常标注、证据引用、统计图表) |
| **调用条件** | 复盘 Agent 周期任务或合规人员按需触发 |
| **依赖工具** | 证据库(执行轨迹/审计快照)、报告渲染服务 |
| **失败处理** | 证据缺失 → 报告标注"证据不完整"并列出缺失项,不掩盖 |
| **安全边界** | 报告只读;仅合规/审计角色可查看;数据脱敏(隐藏报销人敏感信息) |
| **复用价值** | 月度审计、监管报送、供应商风险评估可复用 |
| **与协同流程关系** | 复盘 Agent 的核心输出,支撑经验沉淀与外部审计 |

### 5.3 Skill 版本、发布、回滚与质量评估(赛题 12.2 第 2 条)

- **版本管理**:每个 Skill 带语义化版本号,政策库/规则库版本与 Skill 绑定,发布前灰度(先 10% 单据试跑);
- **发布与回滚**:变更经"设计 → 评审 → 灰度 → 全量 → 观察"流程;回滚保留上一版本,异常时一键回退;
- **质量评估**:通过可观测 Metrics(见 §8.3)评估每个 Skill 的调用成功率、误判率、耗时,回流调优 Prompt/RAG 切片策略。

## 6. MCP 与工具集成(推荐可选项)

### 6.1 MCP 工具清单

| MCP 工具 | 连接对象 | 用途 | 鉴权 |
|---|---|---|---|
| `tax-invoice-verify` | 税务发票验真接口 | 发票真伪与要素核验 | 服务端 API Key + 调用方身份声明 |
| `finance-core` | 财务共享系统/ERP | 单据查询、入账、状态回写 | OAuth2(最小权限) |
| `payment-gateway` | 资金/银行系统 | 付款指令下发与回执 | OAuth2 + 审批回执校验 |
| `notify-message` | 钉钉/企微/邮件 | 人工审批通知、超时提醒 | 应用凭据 |

### 6.2 集成契约(等价契约,满足未用 MCP 时的替代要求)

| 契约项 | 说明 |
|---|---|
| **协议** | 工具统一抽象为 REST 接口,后续迁移 MCP Server 仅需协议适配层,不改工具调用链 |
| **鉴权方式** | OAuth2/API Key 双轨;调用方身份由网关(Higress)统一校验与声明 |
| **输入输出 Schema** | 每个工具声明 JSON Schema(参数、返回结构、错误码),Agent/Skill 按 Schema 稳定调用 |
| **错误处理** | 统一错误码(超时/限流/无权限/数据不存在),Skill 层定义重试、降级策略 |
| **幂等控制** | 付款、入账等写操作带幂等键(单据号+动作),重复调用不产生副作用 |
| **审计记录** | 每次工具调用记录调用方、参数摘要、结果、耗时、TraceId,入审计库 |
| **降级方式** | 外部系统不可用 → 标记人工处理任务,流程不中断、不静默失败 |
| **迁移成本** | 现有契约保持 REST,后续包一层 MCP Server 暴露同名工具即可,无重设计成本 |

## 7. RAG 与上下文增强(推荐可选项,4 选 2 主动声明)

方案采用 **2 项**,符合赛题 9.4"至少实现 2 项":

1. **知识库 RAG(报销政策库)**:
   - 内容:差旅标准、招待标准、采购规则、税务法规、历史稽核案例;
   - 链路:MCP 接入数据源 → Skill 封装检索与证据对齐 → 稽核 Agent 判断检索结果是否支撑决策;
   - 存储:PolarDB for PostgreSQL 向量能力,文档分块 + 向量化,政策按版本隔离。
2. **轨迹可观测(执行证据沉淀)**:
   - 将每笔单据的执行轨迹、决策依据、中间结论持久化,支持全链路回放与审计(详见 §8)。

> 说明:若评审要求额外论证,另可扩展"共享状态管理"(AgentTeams 共享状态承载单据对象,保证并发一致性),成本低、收益明确。

## 8. 可观测设计(推荐可选项,工程落地 20% 权重证据链)

### 8.1 Trace

- 遵循 OpenTelemetry GenAI 语义规范,Span 类型覆盖 **Agent / Skill / MCP / RAG / LLM**;
- 每笔单据生成 TraceId,记录各 Agent 调用顺序、耗时、中间结论;
- 后端:LoongSuite + AgentScope Studio(或阿里云 AgentLoop),支持按 TraceId 回放。

### 8.2 Log

- 结构化 JSON,记录:决策依据(命中的政策条款)、失败原因、权限校验结果、审批事件(审批人/时间/结论);
- 通过 TraceId 与 Trace 关联,审批事件强制全量落盘(合规要求)。

### 8.3 Metrics

| 类别 | 指标 |
|---|---|
| 流量 | 单据处理量、审核通过率/退回率/升级率 |
| 性能 | 端到端处置时延、单环节时延(验真/稽核/审批) |
| 成本 | Token 消耗(按单据/按 Agent)、工具调用成本 |
| 可靠性 | Tool 成功率(验真/支付)、Skill 误判率、支付失败率、审批超时率 |

### 8.4 评估与优化

- 评估方式:规则评估(比对政策条款命中)+ LLM-as-Judge(稽核结论质量打分)+ 人工标注抽样;
- 回流:评估结果回流 Dataset,用于调优 Prompt、RAG 切片与检索策略、Skill 参数;
- 目标:稽核准确率 ≥ 95%、低风险单据自动放行率 ≥ 60%、审批超时率 < 5%。

## 9. 安全、审批、回滚与审计

### 9.1 权限边界

- 按角色最小权限:报销人(提交/查询)、审核人(稽核/审批)、出纳(付款复核)、合规(审计只读);
- 付款金额限额分权,超限自动升级审批链路;
- 密钥/凭据存于密钥管理服务,不出现在代码与配置中。

### 9.2 审批机制(合规红线)

- **AI 不做最终资金决策**:AI 输出建议与风险评级,**打款必须人工确认**;
- 分级审批:金额/风险等级对应不同审批人职级;审批事件全量留痕;
- 审批超时自动升级,不静默通过。

### 9.3 回滚机制

- 支付失败自动回滚并通知;已入账误判单据支持冲销流程(红字冲销/撤回入账);
- 规则/政策误更新支持版本回滚;Skill 版本支持一键回退。

### 9.4 审计机制

- 全链路证据(单据快照、验真回执、政策引用、审批记录、支付回执)关联 TraceId 持久化;
- 审计报告自动生成,满足内部审计与外部监管追溯;
- 数据来源与授权:方案演示使用**模拟脱敏样例**,声明"数据来源为公开政策文档 + 模拟数据,不含真实员工/发票信息",符合赛题 11.1 数据合规要求。

## 附录 A:Agent Identity 清单(赛题 8.2)

### A.1 Intake 单据接收 Agent

- **身份**:流程入口,单据管家
- **目标**:将非结构化单据转化为结构化任务,保证"单进有据"
- **能力边界**:可 OCR 解析、格式校验、去重、任务分派;不可判定费用合规性
- **依赖工具**:OCR 服务、`重复报销检测 Skill`、AgentTeams 任务分派
- **协同关系**:上游=报销人/业务系统;下游=稽核 Agent(推送结构化单据对象)

### A.2 稽核 Agent

- **身份**:政策守门人
- **目标**:按政策条款全量稽核,每项结论附证据引用
- **能力边界**:可调用验真与政策 RAG 并引用出处;不可擅自放宽或臆造政策
- **依赖工具**:`发票真伪核验 Skill`、`报销政策查询 Skill`、`重复报销检测 Skill`
- **协同关系**:上游=Intake Agent;下游=风险评级 Agent(输出判定与证据链)

### A.3 风险评级 Agent

- **身份**:风险裁判
- **目标**:综合风险评级,给出放行/退回/升级建议
- **能力边界**:可评级与建议;不可绕过人工审批发起资金动作
- **依赖工具**:评级规则库、稽核 Agent 结论
- **协同关系**:上游=稽核 Agent;下游=处置 Agent(低风险)/人工审批(高风险)

### A.4 处置 Agent

- **身份**:执行与资金出口
- **目标**:在审批回执完备前提下安全执行付款/入账/退回,保证幂等可回滚
- **能力边界**:可发起付款/入账/退回;**不可在无审批回执时执行任何资金动作**
- **依赖工具**:`支付执行 Skill`、支付系统 MCP、财务系统 MCP
- **协同关系**:上游=风险评级 Agent(低风险)或人工审批结果;下游=复盘 Agent(回执入库)

### A.5 复盘 Agent

- **身份**:组织经验沉淀者
- **目标**:汇总证据链生成审计报告,识别异常模式并建议规则更新
- **能力边界**:可生成报告与规则建议;不可直接修改政策(需政策管理员审批)
- **依赖工具**:`审计报告生成 Skill`、证据库、可观测 Metrics
- **协同关系**:上游=处置 Agent 回执与全链路 Trace;下游=政策库/规则库(经审批回流)
