# 《报销无忧》PPT 优化诊断报告

> 对象:`报销无忧 · 多 Agent 智能稽核与处置闭环.pptx`(18 页,V1.0)
> 方法:python-pptx 版式分析 + 全页文本逐条对照《方案.md》与 2026 GOAI 官方赛题要求
>
> 说明:本报告诊断的是 V1.0;后续优化版 PPT 不随仓库分发(仅保留在本地)。

## 一、总评

**内容质量高,表达过载。** 18 页完整覆盖赛题 12.1 五个评审维度,每页都有"范围/证据/判断"结构,AgentTeams 映射、Skill 九项、合规红线等得分点全部到位。但**信息密度是演示级 PPT 的 3-5 倍**——评委平均 5-10 秒/页,读不完就是损失。

## 二、量化诊断(版式数据)

| 指标 | 实测 | 建议 |
|---|---|---|
| 单页文字量 | 166–1035 字,12 页超 550 字 | 压到 200–350 字/页 |
| 图片/图表数 | **0 张**(纯文字+表格) | 至少 5-6 页配架构图/流程图/指标图 |
| 溢出(元素越界) | 0(排版纪律好) | 保持 |
| 字体 | MiSans(中文)/ Liter(数字) | 一致性好,保留 |

## 三、逐页优化清单

### 全局问题(每页都适用)
1. **"资料来源:参赛方案 v1.0 §x.x"行可删或移入备注**——PPT 是交付物本身,不必每页自证出处;评审不会因引用内部文档加分。
2. **"如何读这一页"块移入演讲者备注**——它是对演讲者说的,不是对观众说的。
3. 每页信息层级降到 3 层:标题结论 → 证据(表格/图)→ 本页判断。

### 单页
| 页 | 问题 | 改法 |
|---|---|---|
| P.03 痛点 | 5 行大表格 + 监管段落 + 目标用户 + 判断,约 600 字 | 痛点表砍到"3 行最重要"(效率/风险/经验);监管并入判断区一句话;目标用户改三张人像卡片 |
| P.04 五维价值 | 表格+输入输出+复制性+60%+ 并存,拥挤 | 五维价值改**雷达/条形图**;"输入输出"精简为左右两栏各 3 行 |
| P.05 架构 | 六层架构是**文字堆叠**,无图形 | 用形状画**分层架构图**(入口→协同→能力→工具→数据/治理),Mermaid 版可直接移植 |
| P.06 Agent 分工 | 表格 5 行 × 4 列,信息密 | 保留表格但删"协同关系"行(已在 P.07 流程体现);与 OpsPilot 对应块精简为 3 行 |
| P.07 8 步闭环 | 8 步 + 审批节点 + 异常表 + 判断,约 750 字 | 8 步改**泳道流程图**;异常表砍到 3 条(验真超时/支付失败/审批超时) |

| P.18 谢谢 | OK | 保留 |

### 数字可视化机会(现在全是文字,建议上图)
- **60%+** 审核人力释放(P.04/P.17)→ 大号数字强调
- **95% 稽核准确率 / 60% 放行率 / <5% 审批超时**(P.12/P.14)→ 指标卡或进度条
- **拦截率 100%**(P.14)→ 语义绿高亮

## 四、优先级建议(时间有限时的顺序)

1. **P.05 架构图、P.07 8 步闭环流程图**——最核心的两张"方案设计"证据,评委必看,文字版最吃亏;
2. **全局减字**:删"资料来源"行、移"如何读这一页"入备注,立刻降噪 30%+;
3. **P.12/P.14 指标卡**:把 3-4 个数字做成大号视觉,一页即可看出量化能力;
4. 其余表格页压缩文字。

## 五、执行方式选项

- **A. 轻量(低风险)**:用 python-pptx 把"资料来源/如何读"移入演讲者备注 + 删冗余括注,不改版式布局;
- **B. 中度**:A + P.05 架构图、P.07 流程图画成形状图(在现有版面内重排);
- **C. 全量重做**:按本报告用 presentation-creator(React 版)重建一版低密度交互式演示(另存新文件,不动原稿)。
